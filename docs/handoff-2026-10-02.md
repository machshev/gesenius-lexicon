# Handoff, 2026-10-02: gold reviewed, ready to measure and decide on the full book

## How to run this session

You are the **orchestrator**. Do not read files, run commands or edit code
yourself. Every piece of work goes to a subagent through the Agent tool, with
a self-contained prompt: the subagent sees none of this conversation, so give
it the paths, commands and acceptance criteria it needs from this file.
Your own job is to:

- pick the next task, choose the model, write the brief;
- read the report, decide, and relay the outcome to the user;
- ask the user before anything that costs real money or time (see the
  cost gates below).

Run independent tasks in parallel, in one message with several Agent calls.
Make each subagent commit its own work; `AGENTS.md` asks for commits as we
go. The attribution line is `Co-Authored-By: <model> <noreply@anthropic.com>`.

### Choosing the subagent model

| Model | Use for | Examples here |
|---|---|---|
| `haiku` | Mechanical work with an unambiguous recipe and checkable output | running scripts and imports, collecting counts, `cargo test`, driving batches |
| `sonnet` | Ordinary engineering: code changes in Python or Rust, tests, debugging with clear evidence, scoring runs | prompt changes, per-script CER/WER scoring, fixing segmentation |
| `opus` | Judgement: reading scans against the output (pointed Hebrew, Arabic, Syriac), checking segmentation, auditing disagreements, reviewing a change | spot-checking a batch, auditing gold disagreements |
| `codex` CLI | An independent second reader from another model family | see below |

Default to the cheapest model that can do the task reliably; move up a tier
when a report comes back wrong or vague. Visual checks of the printed page go
to `opus`. Transcription is done by `claude-fable-5-1` inside the tools.

**Codex as second reader.** `codex exec` subagents may be used as an
independent second reader (the gold review already does this). Give narrow
briefs: the band image and minimal instructions, no page context and no
earlier readings. Codex was wrong on 1 of 4 Hebrew lines it read, so it never
decides alone (two-of-three rule in `docs/ocr-metric-policy.md`). No codex
cost figure is available.

**Token efficiency.** Brief subagents with paths and acceptance criteria, not
file contents. Ask for short reports (counts, paths, commit hashes). Keep
bulk output (logs, diffs, page dumps) out of your own context. Do not re-run
cached steps: pages are cached by image digest and prompt version, and a
prompt version bump makes cached pages re-pay.

### Shell notes for subagent briefs

- The CLI binary is `target/debug/gesenius`; build it with `cargo build`.

  `.cache/gesenius`), `--catalogue`.
- Experiments go in the session scratchpad; copy `corpus/machine` and pass
  `--corpus <copy>` unless the task is an approved import.
- An agent that pipes a script through `tee` or `tail` sees the pipe's exit
  code, not the script's. Use `set -o pipefail` or check `PIPESTATUS`;
  `frontier-verify.py` exits 1 on incomplete records.
- Auto mode blocks killing processes; an agent must not route around that.
  Haiku agents sometimes resend their final report repeatedly; stop them
  with TaskStop once their work is committed.
- Run frontier batches sequentially: concurrent runs hit the usage quota.
